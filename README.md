# Воздушная Москва

Первоначальная рабочая версия интернет-магазина воздушных шаров для Москвы и
Московской области. Сейчас каталог работает на тестовых данных: реальная база,
авторизация и приём заказов будут подключаться отдельными этапами.

## Что уже работает

- мобильная адаптивная главная в едином современном стиле;
- категории, хиты, индивидуальная композиция, преимущества, доставка, примеры
  работ, отзывы, FAQ и контактный блок;
- каталог, категории и карточки товаров;
- корзина с сохранением в браузере;
- демонстрационная форма оформления с проверкой полей;
- страницы доставки, контактов, 404 и ошибок загрузки;
- мобильное меню;
- локальные визуальные заглушки вместо случайных внешних фотографий;
- демонстрационная административная панель;
- проверка TypeScript, ESLint, production-сборка и автоматические тесты маршрутов.

## Технологии

- Next.js 16, App Router и TypeScript;
- React 19;
- Tailwind CSS 4;
- React Hook Form и Zod;
- Zustand;
- ESLint;
- официальный клиент Supabase подготовлен для следующего этапа.

## Требования

- Node.js 22.13 или новее;
- npm.

Supabase для запуска текущей тестовой версии не нужен.

## Точный порядок запуска

1. Откройте терминал в папке проекта.
2. Установите зависимости:

   ```bash
   npm install
   ```

3. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

4. Откройте [http://localhost:3000](http://localhost:3000).

Основная команда для последующих локальных запусков:

```bash
npm run dev
```

Остановить сервер можно сочетанием `Ctrl+C`.

## Переменные окружения

Текущая версия запускается без `.env.local`. Для будущего подключения Supabase
создайте локальный файл на основе безопасного примера:

Windows:

```powershell
Copy-Item .env.example .env.local
```

macOS и Linux:

```bash
cp .env.example .env.local
```

Секретный `SUPABASE_SERVICE_ROLE_KEY` нельзя публиковать, добавлять в Git или
использовать в клиентских компонентах.

## Доступные страницы

| Страница | Адрес |
| --- | --- |
| Главная | `/` |
| Каталог | `/catalog` |
| Категория | `/catalog/[slug]`, например `/catalog/nabory` |
| Товар | `/product/[slug]`, например `/product/nezhnyy-rassvet` |
| Корзина | `/cart` |
| Оформление | `/checkout` |
| Доставка и оплата | `/delivery` |
| Контакты | `/contacts` |
| Административная панель | `/admin` |
| Страница 404 | любой несуществующий адрес |

## Проверка проекта

```bash
npm run lint
npm run typecheck
npm run build
npm test
```

`npm test` ещё раз выполняет production-сборку и проверяет основные маршруты.

## Структура

```text
app/
├── (store)/              покупательские страницы и общий layout
├── admin/                административная часть
├── error.tsx             обработка ошибок
├── loading.tsx           состояние загрузки
└── not-found.tsx         страница 404
components/
├── cart/                 компоненты корзины
├── catalog/              карточки каталога
├── layout/               верхнее меню, мобильное меню и подвал
└── ui/                   базовые компоненты интерфейса
data/catalog.ts           тестовые категории и товары
features/
├── cart/                 состояние и логика корзины
└── checkout/             форма оформления
lib/                      общие функции и подготовленные клиенты Supabase
public/                   статические файлы
tests/                    автоматические проверки страниц
```

## Важные ограничения этапа

- товары и категории пока берутся из `data/catalog.ts`;
- форма оформления не создаёт настоящий заказ;
- административная панель не защищена авторизацией и не изменяет данные;
- онлайн-оплата и расчёт доставки отключены.

Это ожидаемые ограничения первоначальной версии. Следующим отдельным этапом
будут миграции базы и правила доступа Supabase, но он не начинается
автоматически.
